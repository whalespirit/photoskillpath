# A Beginner Photo Folder and Backup System That Stays Findable

<!-- ARTICLE_BODY_START -->

Start with one folder system you can explain in a sentence: put each month’s photos in a dated folder, keep the original files separate from selects and exports, use a predictable filename, and make one additional copy somewhere else. Then test retrieval by finding one named photo from the backup. A system is useful when you can locate a file without relying on memory or one app’s search view.

This is a small, device-agnostic workflow, not a cloud-provider comparison. It works for a month of phone photos, a camera card, or a mixed import. The folders and names create findability; the second copy reduces the chance that one device failure removes the only file.

## The smallest useful folder tree

For one month, create a structure like this:

```text
Photos/
  2026/
    2026-11/
      originals/
      selects/
      exports/
      notes.txt
```

Put the untouched imports in `originals`. Put the images you may actually share in `selects`. Put resized or destination-specific copies in `exports`. The names are labels, not a requirement to use one particular app. A text file can hold a short note about the month, the device, or a missing date.

The National Archives recommends organizing selected digital photos into related groups, using descriptive names, and keeping a directory structure that can be explained later. Microsoft Photos also supports folders and search on Windows, which illustrates the practical benefit of keeping files in locations you can browse outside a single editor.

## A filename that survives a moved file

Use a pattern that still makes sense if the image leaves its folder:

```text
2026-11-10_window-light_001.jpg
2026-11-10_window-light_002.jpg
2026-11-10_window-light_select.jpg
```

The date sorts naturally, the subject gives context, and the number separates similar frames. Keep the pattern short enough to repeat. Use letters, numbers, hyphens, or underscores rather than spaces and punctuation that may behave differently across systems. Keep the original file extension; changing a name is not the same as converting a file.

If the exact date is unknown, use the most reliable date you have and record the uncertainty in `notes.txt` rather than inventing a precise day. The Library of Congress describes descriptive naming and keeping metadata with the files as practical ways to make older images identifiable later.

## One-month example: import, select, export

Imagine a month of phone photos spread across a camera roll, a downloads folder, and a messaging app. Do not start by renaming every file in the library. Start with one month:

1. Create the dated month folder and its four parts.
2. Copy the month’s source files into `originals`; do not edit or delete them during sorting.
3. Choose a small set for `selects` and give the copies meaningful names if the original names are opaque.
4. Create `exports` only for files prepared for a known purpose, such as a web share or a print order.
5. Add a short note describing what the folder contains and where the second copy lives.

This sequence keeps the source file available while you decide what to share. If an app offers “save as copy,” use that for an edited version when you want the original untouched. Google Photos documents this distinction: saving in place changes the working item, while saving as a copy creates a separate edited photo.

## Make the second copy, then verify it

The minimum practical system has the working folder plus one separate copy. The second copy can be an external drive, a computer folder, or a cloud service, but it should not be treated as complete merely because a switch says “backup.” Google Photos lets users choose device folders for backup and check whether a particular photo has been backed up. That check is more useful than assuming every folder on a phone is included.

For an irreplaceable archive, the U.S. National Archives recommends a stronger pattern: multiple copies on different media, with one copy kept in another location. That is a preservation target, not a promise that a beginner must build a complex archive on day one. Start with the second copy, then add another location as the collection becomes more important.

Do not confuse synchronization with an independent backup. A synchronized folder may mirror deletions or edits, depending on the service. Before removing a phone copy, open the cloud or external copy and confirm that the file is present, readable, and the version you intend to keep.

## The five-minute retrieval test

After organizing one month, test the system with a question you might ask later: “Find the third window-light photo from November.” Use the filename or folder, open the file, and compare it with the copy in the second location.

Record four results:

- Can you locate the month folder without searching every app?
- Does the filename identify the subject or event?
- Can you open the backup copy on a different device or drive?
- Do you know which file is the original and which is the export?

If one answer is no, repair that part before importing another month. A retrieval test is a small quality check; it is not a guarantee against hardware failure, account loss, or future format problems.

## Where albums and tags fit

Albums are useful views for a person, trip, or project, but they do not have to replace folders. Apple Photos, for example, lets users create named albums and organize albums into folders; Google Photos can search and back up selected device folders. These tools can help you browse, while the dated folder and filename remain a portable base layer.

Use one album for a theme that crosses months, such as “window light practice,” and keep the files in their dated folders. That gives you a convenient view without making the theme the only location where the image exists.

## When to add complexity

Add more structure only after the small system has survived a few retrieval tests. You may then want a separate archive for scans, a version suffix for major edits, or a spreadsheet for a long-running project. Do not begin with a dozen categories, a provider comparison, or a promise of permanent safety. The next useful improvement is the one that makes a real file easier to find or recover.

Your finished system should pass one simple sentence: “I know where the original is, where the shareable copy is, and where the second copy can be opened.” If you cannot say that yet, fix the folder, name, or backup check before adding another month.
